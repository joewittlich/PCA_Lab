Translate the first on-call handoff lesson

Use this guide to prepare a version that a new responder can read, discuss, and use to ask a teammate for help. The source language is US English.

  • Prepare the files

Prepare the files

  1. Read the lesson once as a learner. Notice where the learner makes a prediction, gives a handoff, and opens the reveal.
  2. Create a folder beside en-US. Give it a BCP 47 language tag. Use an ISO 639 language code, such as ar for Arabic. Add a script (ISO 15924) or region (usually ISO 3166-1) when it identifies the intended audience. For example, zh-Hans means Chinese written in Simplified script, and en-US means English as used in the United States. Join subtags with hyphens.
  3. Copy strings.json and terminology.json into the new folder. Set locale in both copies to your tag. Save the files as UTF-8. Work from the English copy for the meaning of each message.

The strings object contains pairs. A key identifies a piece of lesson text. Its value is the text a reader sees. Each key also appears in the lesson HTML as a data-key attribute. Use the key to find the same text in either file.

Choose terms a responder would use

Open the full term list in a text editor. Search for a concept such as held_out. Each concept has a preferred term, its meaning, guidance for this lesson, and any exact labels from the evidence. Keep the concept ID. In your copy, enter the accepted local wording in preferred and translate meaning and context. Copy machine_tokens exactly.

P95 request time
Roughly 95 out of 100 requests finished within the stated time. Keep “about” with each estimate. One user task may require several requests.
Baseline and held-out normal samples
The model learned its pattern and threshold from the baseline samples. The team reserved the held-out normal samples to check the detector afterward. A summary from a current run may also list after_run, the samples after the scenario's recorded end. Those samples are not held-out normal. Copy the machine token after_run exactly.
Principal component analysis (PCA)
A method for describing how measurements vary together. Introduce the full name when teaching the abbreviation.
Score and threshold
The score measures how far a sample falls from the learned pattern. It has no time units. The detector flags the sample when the score is above the threshold.
Flag and page
To flag is to mark a sample. To page is to send an urgent notification to a person. Choose two distinct verbs.
Biggest contributor
The measurement that accounts for the largest part of a sample’s score. The responder still needs evidence about the cause.
Handoff
A short update for the next responder. It gives a measured observation, explains what is uncertain, and names a check that could change the response.

Translate the text

Each standalone prediction exercise has its own page and catalog. Use the same page name in the Python command and file name. For example, copy direction.strings.json into the target folder, set its locale, translate its values, and run python localize.py ar --dir rtl --page direction for Arabic. The other catalogs are training.strings.json and readings.strings.json. Use --page training or --page readings for those exercises. The same page option works with --extract and --check. Preserve the direction diagram’s square and diamond references so a reader can identify each sample without color.

Translate the values in strings.json. Keep the keys. Read the neighboring messages to learn who is speaking and what the learner knows at that point. Use one familiar term for each concept, short sentences, and direct questions. Preserve choices to speak, write, work alone, or work with a partner.

Work with a translator or a language model

Give the translator the source messages for one section, its place in the lesson, the term list, and the target language tag. Ask for the same keys with translated values. For example, give this instruction for the score table:

Translate the table for a new responder. Use our preferred words for “score” and “flag.” The first crossing shown occurs at 00:18:38 UTC. Preserve which measurement contributed most in each row. Keep the fault reveal for later. Mark any word choice that a local on-call responder should review in a separate note.

Ask a second reader to explain the translation in their own words or translate it back into English. Ask which measurement contributed most at the crossing. The answer is average request time. If the reader answers p95 or says a cause was proven, revisit that row and its explanation.

Keep the evidence traceable

Use local number separators and date conventions in displayed text. For example, the score displayed as 117,321.909 has a whole-number part of 117321 and a fractional part of 909 thousandths. Keep the same value, precision, units, time order, and UTC reference. Keep the evidence CSV and JSON exactly as recorded, including column names, timestamps, decimal points, and labels such as fault_latency.

Keep file paths, link targets, HTML IDs, and message keys exact. If a message has a placeholder, copy its spelling and delimiters and move it where the grammar requires. A blank in a handoff starter is space for the learner’s answer. Leave room for that answer.

Build the local page

If you change the US English lesson, run python localize.py --extract in the first-on-call folder to update its catalog. Run python localize.py --check to check the catalog.

For a manual edit, copy en-US/index.html into the target folder. In a UTF-8 text editor, find each data-key and replace its text with the matching translated value. Include the browser title, links, prompts, and control labels. Preserve the HTML markup and the key itself. Escape literal < and & in HTML text as &lt; and &amp;.

Alternatively, run the included Python tool from the first-on-call folder. For Arabic, save the translated ar/strings.json, then run python localize.py ar --dir rtl. The tool writes ar/index.html. The default direction is ltr. Use --force only when you intend to replace an existing target page. Maintain the term list and this guide separately. If you link to a target-language guide, place that file beside its lesson.

On each translated HTML page, set lang on the root html element to the folder’s tag. Set dir="rtl" for Arabic or dir="ltr" for horizontal Simplified Chinese. Set the language on passages left in another language. Keep fixed left-to-right identifiers or timestamps together in RTL text, for example <bdi dir="ltr">00:18:38 UTC</bdi>. Keep CSS properties such as margin-inline-start so spacing follows the reading direction.

Review the lesson with a local reader

  • Open the target index.html directly from disk with the network off. Read its tab title, follow each link, and open the reveal. Check that learners can pause before the answer is visible.
  • Compare every target key with the English list. Check labels, names read aloud by assistive technology, and resource links in the rendered page. Keep the target string values and the HTML text in sync after any manual edit.
  • Ask the reader to give a handoff. Listen for a measurement with units, a statement of uncertainty, and a next check. Ask how many slowdowns the seven labeled samples represent. The recording contains one slowdown.
  • Use the keyboard to reach and operate the links and controls. Check that focus stays visible. Increase text size to 200% and test on a narrow screen. Read the longest prompt and follow a table row from its time to its contributor.
  • For an RTL translation, inspect the table order and the punctuation beside timestamps and Latin identifiers. For Chinese, Japanese, or Korean, inspect line breaks around punctuation and the display of all characters in the local system font. Check that numbers and units stay understandable when lines wrap.

For details about language tags and direction, see the W3C guides to language tags and right-to-left text in HTML (online).
