New timestamps, repeated readings

This five-minute exercise uses generated data. A principal component analysis (PCA) model learns how CPU use and request rate change together. Its score measures how far a pair of readings falls from the learned line.

With a partner, one person predicts what the model will flag. The other asks what to check for people using the service. On your own, answer both questions. Speak or write before you open the result.

Read the case and make a prediction

A collector reports the same pair of values 20 times: about 15.74 requests per second and 0.154 CPU cores. Each sample arrives with a new timestamp, 15 seconds after the previous one. The pair came from a healthy period.

Show the result and discuss the next check

The detector flagged 0 of 20 samples. It scored each pair separately. Each score was about 0.00061. In this simulation we copied the values and gave each copy a new timestamp.

Compare the request count with a separate source, such as access logs for the same period. Check when the sensor last measured the service. What would you tell your teammate if the logs showed changing traffic?

Discuss one observation, one uncertainty, and one check. Revise your answer if the discussion changes your decision.
